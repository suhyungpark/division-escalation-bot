# 확전 번역봇 v13

디비전2의 **일일 확전 지정 전리품**을 한글 이미지로 만들어 디스코드에 올린다.
영문 봇 `Daily Escalation Target Loot`의 글을 읽어 번역·렌더링한 뒤 같은 채널에 게시한다.

v12는 exe만 남고 소스가 소실되어, exe에서 구조만 복원한 뒤 처음부터 새로 작성했다.

---

## 어떻게 도는가

```
GitHub Actions (3시간마다)
   └─ bot.py --watch 300
        ├─ discord_client  채널 최근 글에서 원문 봇 메시지를 찾는다 (REST만, 상시 연결 없음)
        ├─ parser          구·신 두 형식을 모두 읽어 날짜·임무·벤더로 분해
        ├─ translator      영문 이름 -> 한글·카테고리·아이콘
        ├─ pipeline        세트 효과를 붙이고 렌더러가 먹는 모양으로 조립
        └─ renderer        Pillow로 PNG 한 장 (가로 1080px)
```

**상시 연결(Gateway)을 쓰지 않는다.** 깨어나서 훑고 끝내므로 컴퓨터를 켜둘 필요가 없고,
봇이 꺼져 있던 동안 올라온 글도 잡는다.

### 왜 `--watch` 인가

GitHub 예약 실행은 **지정한 시각을 지키지 않는다.** 실측(2026-08-28~29)으로
`00:08` · `21:21` · `07:53` UTC 에 돌았는데 어느 것도 지정한 슬롯이 아니었다.
8/29에는 07:53에 깨어났는데 원문이 08:24에 올라와 **31분 차이로 빗나갔다.**
슬롯을 3개→21개로 늘려도 해결되지 않았다.

그래서 시각을 맞추려 애쓰는 대신 **깨어난 뒤 새 글이 올 때까지 자리를 지킨다.**
3시간마다 깨우고 최대 5시간 지켜보므로, 어느 슬롯이 걸리든 그날 게시 시각을 덮는다.
(공개 저장소여야 Actions 시간 제한이 없어 이 방식이 가능하다.)

깨우는 주기보다 지켜보는 시간이 길어 실행이 늘 겹친다. 그대로 두면 원문이 올라온
순간 두 실행이 거의 동시에 확인해 같은 그림이 두 번 나갈 수 있으므로, 워크플로의
`concurrency` 로 새로 깨어난 쪽에 자리를 넘겨 언제나 하나만 지켜보게 한다.

지켜보는 동안의 통신 오류는 **마지막에 본 상태만** 종료코드에 반영한다. 다섯 시간
중 한 번 끊긴 것을 끝까지 들고 가면 제대로 게시하고도 실행이 빨간 X로 남아,
진짜 고장과 구분이 안 된다.

## 번역이 아니라 찾아보기

원문 봇이 쓰는 어휘는 **닫힌 집합**이다 — 무기 7 · 보호장구 부위 8 · 브랜드 37 ·
보호장구 세트 27 · 임무 25, 다 합쳐 100여 개. 새 시즌에나 몇 개 늘어난다.

그래서 기계번역이 아니라 사전으로 푼다. 기계번역은 인게임 표기를 알 리가 없다
(`Holster` → 홀스터 ✗ / 권총집 ✓).

| 단계 | 처리 | 비용 |
|---|---|---|
| 1 | 카탈로그에서 그대로 찾기 | 0 |
| 2 | 대소문자·기호·복수형을 없애고 다시 찾기 | 0 |
| 3 | 편집거리로 가장 가까운 것 | 0 |
| 4 | DeepL | API 호출 |

2단계가 `Holster`/`Holsters`, `Walker, Harris & Co`/`...& Co.` 같은 표기 흔들림을
흡수한다. v12는 이 단계가 없어 별칭을 손으로 9쌍 적어두고 있었다.

4단계까지 간 항목은 이미지에 **회색 + 주황 별표**로 나가고 `overrides.json`에
자동으로 적힌다. 다음 실행부터는 1단계에서 걸린다.

## 파일

| | |
|---|---|
| `bot.py` | 진입점 |
| `parser.py` · `translator.py` · `pipeline.py` | 읽기 → 번역 → 조립 |
| `renderer.py` · `textkit.py` · `config.py` | 그리기. 색·크기·문구는 전부 `config.py` |
| `build_catalog.py` | `catalog.json` 생성 (실행 전 1회) |
| `apply_patch.py` | 게임 패치 노트를 세트 효과에 반영 |
| `data/overrides.json` | **손으로 고치는 곳** — 이름 수정, 검토 대기 목록 |
| `data/set_effects.json` | **손으로 고치는 곳** — 세트 효과 |
| `data/icons/` | 79개. 위키 배지에서 원형 배경을 벗겨 인게임 모양으로 |
| `data/fonts/` | Pretendard (OFL). 리눅스에서도 같은 그림이 나오게 |

`catalog.json`은 생성물이라 저장소에 없다. `translation_table.json`은 v12 유산이며
수정은 `overrides.json`에서 덮어쓰는 방식으로 한다.

### 손으로 돌릴 때

```bash
python build_catalog.py            # 사전을 고쳤으면 먼저
python bot.py --dry-run            # 읽되 보내지 않음
python bot.py                      # 실제 전송
python bot.py --file tests/xxx.txt # 디스코드 없이 그림만
```

환경변수: `DISCORD_TOKEN`, `DISCORD_CHANNEL_ID`(쉼표로 여러 개), `DEEPL_API_KEY`(선택)

## 지켜온 원칙

**게임 용어를 추측해서 채우지 않는다.** 근거가 없으면 비워두고 표시한다.
실제로 논리적 추론이 세 번 틀렸다 — `브랜드 세트`(제안 `브랜드`), `2+ 개`(제안 `2부위`),
`Gear Set`(제안 `장비 세트`, v12가 맞았음). 매번 인게임 스크린샷이 정답이었다.

**나무위키에서 표를 뽑을 때는 대조군을 함께 넣는다.** 항목이 많은 표에서 행이 어긋나도
그럴듯한 문장으로 나온다. 실제로 `페트로프 방위 그룹`에 `리히터 & 카이저`의 값이
들어간 채 디스코드 두 곳에 나갔다. 이후로는 인게임으로 확인된 항목
(`길라 가드` · `코어 근력` · `오티즈: 엑수로`)을 질의에 함께 넣어, 그 값이 맞게
나올 때만 나머지를 신뢰한다. 이 방식으로 옮긴 `상태이상 저항`은 나중에 인게임
화면(`오티즈: 레피세레`의 4부위 본문)에서 그대로 확인됐다.

**조용히 실패하지 않는다.** 데이터가 없으면 '준비 중' 카드로, 사전에 없으면
회색 별표로 드러낸다. v12는 무기 아이콘이 깨진 줄도 몰랐다.
